# Описание TO-BE процесса

## Общее видение

После внедрения интеграции процесс создания заказа на доставку становится
полностью автоматическим — от момента подтверждения заказа клиентом до
получения трек-номера в CRM. Менеджер подключается только в нештатных ситуациях.

---

## Шаги процесса

**Шаг 1. Клиент оформляет заказ**
Клиент на сайте магазина TechDrop заполняет форму — выбирает товары, вводит
адрес доставки и контактные данные. Сразу после ввода адреса система магазина
автоматически отправляет его на валидацию в API СДЭК.

**Шаг 2. Клиент видит расчёт стоимости и срока**
API СДЭК возвращает результат валидации — стоимость и срок курьерской доставки.
Система отображает их клиенту до подтверждения заказа. Если адрес не покрыт
доставкой — клиент видит ошибку и может скорректировать адрес.

**Шаг 3. Клиент оплачивает заказ**
Клиент подтверждает заказ и производит оплату. После подтверждения платежа
система магазина автоматически формирует запрос POST /orders к API СДЭК
с уникальным idempotency key для защиты от дублей.

**Шаг 4. Gateway — ответ получен?**
Система ожидает ответ от API СДЭК. Процесс разветвляется:
- 200 OK — API вернул успешный ответ, процесс идёт дальше
- 5xx / timeout — запрос уходит в очередь retry, повторяется до 4 раз
с нарастающей задержкой: 1 мин → 5 мин → 15 мин → 1 час.
После исчерпания попыток — алерт менеджеру.

**Шаг 5. СДЭК регистрирует отправление**
API СДЭК принимает запрос и создаёт отправление в своей системе.

**Шаг 6. СДЭК возвращает cdek_order_uuid**
API возвращает уникальный идентификатор отправления. Система магазина
сохраняет его в CRM и связывает с заказом.

**Шаг 7. Система отправляет трек-номер клиенту**
После сохранения cdek_uuid система магазина отправляет клиенту email
с трек-номером и ориентировочным сроком доставки.

**Шаг 8. СДЭК отправляет webhook статуса**
При каждом изменении статуса отправления СДЭК отправляет webhook-уведомление
на эндпоинт магазина. Шаги 8-10 повторяются при каждом изменении статуса.

**Шаг 9. Система принимает и верифицирует webhook**
Система магазина получает входящий запрос, проверяет подпись и обрабатывает
новый статус.

**Шаг 10. Система уведомляет клиента об обновлении статуса**
Статус обновляется в CRM, клиент видит актуальный статус в личном кабинете
и получает push или email уведомление.

**Шаг 11. Конец**
При получении статуса DELIVERED процесс завершается. Заказ закрывается в CRM,
клиент получает финальное уведомление о доставке.

## Gap Analysis AS-IS → TO-BE

| Параметр | AS-IS (сейчас) | TO-BE (после) |
|---|---|---|
| Создание накладной | Вручную, менеджер | Автоматически, ~2 сек |
| Время обработки заказа | ~15 минут | ~2 минуты |
| Источник ошибок | Человеческий фактор | Валидация на этапе ввода |
| Статусы доставки в CRM | Обновляются вручную | Автоматически через webhook |
| Масштабируемость | Ограничена числом менеджеров | Горизонтально масштабируется |
| Стоимость операции | ~1 ставка менеджера | Только инфраструктура |
