# Метрики и Risk Register

## Метрики

### M-01 — Время обработки заказа

| Параметр | Значение |
|---|---|
| Описание | Время от подтверждения оплаты до появления трек-номера в CRM |
| Baseline | ~15 минут (ручной процесс) |
| Цель | ≤ 2 минуты |
| Как собираем | Timestamp оплаты и timestamp сохранения cdek_uuid — разница |
| Инструмент | Логи CRM / BI-дашборд |
| Owner | Product Owner |

### M-02 — Процент успешного создания отправлений

| Параметр | Значение |
|---|---|
| Описание | Доля заказов по которым отправление создано автоматически без ручного вмешательства |
| Baseline | 0% (сейчас всё вручную) |
| Цель | ≥ 97% |
| Как собираем | Количество заказов в статусе shipment_created / общее количество × 100 |
| Инструмент | Мониторинг очереди задач + логи |
| Owner | Backend-разработчик |

### M-03 — Процент ошибок при создании накладных

| Параметр | Значение |
|---|---|
| Описание | Доля запросов к API СДЭК завершившихся ошибкой |
| Baseline | н/д (интеграции не было) |
| Цель | ≤ 1% после стабилизации |
| Как собираем | Логи запросов к API, группировка по кодам ответа |
| Инструмент | Grafana / Sentry |
| Owner | Backend-разработчик |

### M-04 — Время обновления статуса доставки у клиента

| Параметр | Значение |
|---|---|
| Описание | Задержка между изменением статуса в СДЭК и отображением у клиента |
| Baseline | До 24 часов (менеджер обновлял вручную раз в день) |
| Цель | ≤ 5 минут |
| Как собираем | Timestamp webhook от СДЭК и timestamp обновления статуса в БД |
| Инструмент | Логи webhook-обработчика |
| Owner | Backend-разработчик |

### M-05 — Операционная нагрузка на менеджера

| Параметр | Значение |
|---|---|
| Описание | Количество заказов требующих ручной обработки в день |
| Baseline | 500 заказов/день (100% ручных) |
| Цель | ≤ 15 заказов/день |
| Как собираем | Количество задач в статусе requires_manual_processing в CRM за день |
| Инструмент | CRM-отчёт |
| Owner | Менеджер по заказам |

## Risk Register

| Риск | Вероятность | Влияние | Приоритет | Митигация |
|---|---|---|---|---|
| API СДЭК меняет структуру запроса без предупреждения | Низкая | Высокое | Высокий | Мониторинг changelog API СДЭК, версионирование интеграции, алерт при росте 4xx |
| Утечка API-ключей СДЭК | Низкая | Критическое | Высокий | Хранение в переменных окружения, ротация ключей раз в 90 дней, запрет коммита в репозиторий |
| Рост объёма заказов превышает rate limit СДЭК | Средняя | Среднее | Средний | Отслеживать метрику 429-ошибок, заранее согласовать увеличение лимита с СДЭК |
| Потеря webhook при недоступности эндпоинта магазина | Средняя | Среднее | Средний | Polling как fallback каждые 6 часов, алерт при расхождении статусов |
| Ошибки маппинга адресов | Высокая | Среднее | Средний | Тестирование на реальных адресах до запуска, валидация на этапе ввода |
| Задержка запуска из-за отсутствия доступа к sandbox СДЭК | Средняя | Низкое | Низкий | Запросить доступ к тестовой среде на этапе анализа, не перед разработкой |
