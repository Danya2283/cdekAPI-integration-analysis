# Глоссарий

| Термин | Определение |
|---|---|
| API | Интерфейс для взаимодействия двух систем по заранее установленным правилам. В нашем случае — способ общения системы магазина с системой СДЭК |
| REST API | Архитектурный стиль построения API, где запросы отправляются по HTTP и возвращают данные в формате JSON |
| POST /orders | Конкретный метод API СДЭК для создания нового отправления. POST — тип запроса, /orders — адрес эндпоинта |
| Эндпоинт | Конкретный адрес в API куда отправляется запрос. Например: api.cdek.ru/v2/orders |
| Webhook | Механизм автоматического уведомления — СДЭК сам отправляет сообщение в систему магазина когда статус отправления меняется |
| Idempotency Key | Уникальный идентификатор запроса. Защищает от создания дублей — если запрос повторился, система понимает что это тот же запрос и не создаёт второе отправление |
| cdek_order_uuid | Уникальный идентификатор отправления в системе СДЭК, который возвращается после успешного создания заказа |
| Retry / Очередь retry | Механизм повторной отправки запроса при ошибке. Запрос помещается в очередь и повторяется через определённые интервалы времени |
| Rate Limit | Ограничение на количество запросов к API за единицу времени. Превышение лимита возвращает ошибку 429 |
| HTTP 200 OK | Код ответа сервера означающий что запрос выполнен успешно |
| HTTP 400 Bad Request | Код ответа означающий что запрос содержит ошибку — например неверный формат данных |
| HTTP 401 Unauthorized | Код ответа означающий что запрос не прошёл авторизацию — неверный или истёкший ключ |
| HTTP 429 Too Many Requests | Код ответа означающий что превышен лимит запросов к API |
| HTTP 5xx | Группа кодов означающих ошибку на стороне сервера — система временно недоступна |
| Sandbox | Тестовая среда API СДЭК где можно проверять интеграцию без создания реальных отправлений |
| CRM | Система управления взаимоотношениями с клиентами. В контексте проекта — внутренняя система магазина где хранятся заказы и статусы |
| Маппинг полей | Соответствие между полями в системе магазина и полями в API СДЭК. Например поле «адрес» в CRM → поле address в запросе к API |
| NFR | Нефункциональные требования — требования к тому как система работает: скорость, надёжность, безопасность |
| MVP | Minimum Viable Product — минимально рабочая версия продукта с базовым набором функций достаточным для первого запуска |
| Polling | Периодические запросы от системы магазина к API СДЭК для получения актуальных статусов. Используется как резервный механизм если webhook не пришёл |
| Timestamp | Точная метка времени события записанная в базу данных. Используется для расчёта метрик и диагностики проблем |
| Uptime | Процент времени за период когда система работала без сбоев |
| RTO | Recovery Time Objective — максимально допустимое время восстановления системы после сбоя |
| RPO | Recovery Point Objective — максимально допустимый объём потерянных данных при сбое |
| BPMN | Стандартная нотация для визуального описания бизнес-процессов |
| Swimlane | Дорожка на BPMN-схеме обозначающая зону ответственности конкретного участника процесса |
| RACI | Матрица распределения ролей: R — выполняет, A — отвечает за результат, C — консультирует, I — информируется |
