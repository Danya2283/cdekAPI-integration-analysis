# Нефункциональные требования (NFR)

## Производительность

| Требование | Метрика | Значение |
|---|---|---|
| Время ответа при валидации адреса | 95-й перцентиль | ≤ 3 секунды |
| Время создания отправления POST /orders | 95-й перцентиль | ≤ 5 секунд |
| Обновление статуса в ЛК после webhook | От получения до отображения | ≤ 5 минут |
| Пропускная способность без деградации | Заказов в час | ≥ 100 заказов/час |

---

## Надёжность и доступность

| Требование | Значение |
|---|---|
| Uptime интеграционного модуля | ≥ 99.5% в месяц |
| Время восстановления после сбоя (RTO) | ≤ 30 минут |
| Допустимая потеря данных при сбое (RPO) | 0 — ни один оплаченный заказ не теряется |
| Гарантия доставки сообщений в очереди | At-least-once |

---

## Безопасность

| Требование | Реализация |
|---|---|
| Хранение API-ключей СДЭК | Только в переменных окружения, не в коде |
| Верификация входящих webhook | Проверка подписи, отклонение при несовпадении |
| Передача данных | Только по HTTPS |
| Логирование событий безопасности | Все отклонённые webhook пишутся в лог с IP и временем |
| Ротация API-ключей | Раз в 90 дней без остановки сервиса |

---

## Масштабируемость

| Требование | Значение |
|---|---|
| Горизонтальное масштабирование | Несколько инстансов без конфликтов |
| Рост нагрузки | Выдерживает рост в 3× без архитектурных изменений |

---

## Сопровождаемость

| Требование | Значение |
|---|---|
| Логирование запросов к API СДЭК | Запрос, ответ, код статуса, время |
| Алертинг | Уведомление в мониторинг в течение 5 минут при росте ошибок |
| Документация интеграции | Актуальная документация эндпоинтов и сценариев ошибок |
