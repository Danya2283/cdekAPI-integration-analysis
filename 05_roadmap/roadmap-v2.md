# Пути развития (Roadmap)

## v2 — Следующая итерация после MVP

### RD-01 — Подключение ПВЗ и постаматов

Что: добавить возможность выбора пункта выдачи и постамата при оформлении
заказа — сейчас в скоупе только курьерская доставка до двери.

Зачем: 30% заказов магазина потенциально идут в ПВЗ — неохваченный сегмент
автоматизации.

Что потребуется: интеграция с методом GET /deliverypoints для отображения
карты ПВЗ, новый UI-компонент выбора точки, расширение маппинга полей заказа.

---

### RD-02 — Личный кабинет трекинга для клиента

Что: отдельная страница в личном кабинете с картой движения посылки,
историей статусов и ожидаемым временем доставки.

Зачем: визуальный трекинг снижает нагрузку на поддержку — клиент сам
видит где посылка.

Что потребуется: виджет карты (Яндекс.Карты API), хранение истории статусов
в БД магазина, отдельный эндпоинт для фронтенда.

---

### RD-03 — Автоматический возврат

Что: при статусе NOT_DELIVERED после N попыток вручения — автоматически
инициировать возврат отправления на склад магазина через API СДЭК.

Зачем: сейчас менеджер делает это вручную. При росте объёма — узкое место.

Что потребуется: обработка статуса RETURN в webhook-обработчике, новый
сценарий в матрице ошибок, уведомление клиента с предложением повторного заказа.

---

### RD-04 — Аналитический дашборд доставок

Что: дашборд для руководства с метриками — процент успешных доставок,
среднее время доставки по городам, доля возвратов.

Зачем: даёт видимость процесса на уровне бизнеса, позволяет выявлять
проблемные направления доставки.

Что потребуется: хранение всех webhook-событий в аналитической таблице,
BI-инструмент (Metabase / Power BI).

---

### RD-05 — Мультиперевозчик

Что: выбор перевозчика автоматически на основе цены, срока и зоны доставки —
СДЭК, Boxberry, Почта России.

Зачем: снижение стоимости доставки за счёт конкуренции перевозчиков,
расширение географии.

Что потребуется: абстрактный слой интеграции с единым интерфейсом для всех
перевозчиков, логика выбора оптимального варианта.

---

## Приоритизация по MoSCoW

| Функция | Приоритет | Обоснование |
|---|---|---|
| ПВЗ и постаматы | Must Have v2 | 30% потенциальных заказов |
| Трекинг в ЛК | Should Have | Снижает нагрузку на поддержку |
| Автовозврат | Should Have | Узкое место при росте объёма |
| Аналитический дашборд | Could Have | Полезно, но не критично на старте |
| Мультиперевозчик | Won't Have v2 | Сложная архитектура, отложить до v3 |
